## PXF 6.10.4

Released: 20 Nov 2026

::: info Note
Before you upgrade, see [Upgrading PXF](../installing.md#upgrading-pxf) for changes that might affect existing external tables.
:::

### Enhancements

- You can now write `NUMERIC(<precision>, <scale>)` columns with a precision above 38, up to 76, to Parquet. Previously, PXF rejected any precision above 38. This change has the following effects:
    - PXF writes the column as a Parquet `DECIMAL` on a `FIXED_LEN_BYTE_ARRAY`, which is 32 bytes at precision 76.
    - Arrow-based readers such as PyArrow read the column as `decimal256`.
    - Spark, Hive, and other readers limited to precision 38 can't read the column.
    - Precision up to 38, the `DECIMAL(38,18)` mapping of an unconstrained `NUMERIC`, and ORC writes are unchanged.

### Bug fixes

- Fixed the error and warning messages for a `NUMERIC[]` value that doesn't fit the Parquet decimal type on write. The messages named the table's first column instead of the array column. Only the column name in the messages was wrong, not how PXF handled the value.
- Fixed CSV quoting in the `DemoTextResolver` example plugin. Values containing the delimiter, a quote or escape character, or a line break were written without quoting, so the line didn't read back as the row that was written. CSV tables are now quoted, and `TEXT` tables are written as-is. Real connectors weren't affected.
- Fixed a segment crash when a `pxfdelimited_import` external table set `QUOTE` without `DELIMITER`. It now fails with `missing delimiter option`.

### Security

- Fixed [CVE-2024-47561](https://nvd.nist.gov/vuln/detail/CVE-2024-47561), a code execution vulnerability when reading Avro files. This fix includes:
    - **Cause:** The `*:avro` profiles used Avro's `SpecificData` model, which loads Java classes named in the schema. A crafted file on a table's path could run code in the PXF JVM.
    - **Fix:** PXF now uses Avro's `GenericData` model, which never loads classes named by the schema. Values read from ordinary Avro files are unchanged.
    - **Behavior change:** PXF now ignores `java-class` and `java-key-class` in a schema and reads the value as a string. Previously, a class that PXF doesn't ship caused a `ClassNotFoundException`.
- Upgraded the bundled libraries in the following table. The Hadoop 2.10, Hive 2.3, and HBase 1.3 client runtimes are unchanged.

| Library | Previous version | New version | Fixes |
|---------|------------------|-------------|-------|
| `snappy-java` | 1.1.10.4 | 1.1.10.12 | BDSA-2026-33684, BDSA-2026-33873, and buffer-overflow and allocation issues. Crafted Snappy data in Parquet or Avro files could make a read allocate up to 2 GB and stop the PXF server. |
| `aircompressor` | 0.8 | 2.0.3 | [CVE-2024-36114](https://nvd.nist.gov/vuln/detail/CVE-2024-36114) and [CVE-2025-67721](https://nvd.nist.gov/vuln/detail/CVE-2025-67721). Crafted ORC data could crash the JVM or leak memory contents. |
| Avro | 1.10.2 | 1.11.5 | [CVE-2023-39410](https://nvd.nist.gov/vuln/detail/CVE-2023-39410) (unbounded allocation). Also fixes [CVE-2024-47561](https://nvd.nist.gov/vuln/detail/CVE-2024-47561) in the library itself. |
| Jackson | 2.13.5 | 2.22.4 | [CVE-2025-52999](https://nvd.nist.gov/vuln/detail/CVE-2025-52999) (stack overflow on deeply nested JSON), and later `jackson-core` and `jackson-databind` advisories. |
| `libthrift` | 0.9.3 | 0.9.3-1 | [CVE-2018-1320](https://nvd.nist.gov/vuln/detail/CVE-2018-1320). The Thrift client didn't check that SASL negotiation with the Hive metastore or HiveServer2 had completed. |
| `parquet-format` | 2.7.0 | 2.10.0 | [CVE-2020-13949](https://nvd.nist.gov/vuln/detail/CVE-2020-13949). A crafted Parquet file could stop the PXF server. Parquet reads now fail on a file whose footer holds a single value larger than 100 MB. |

- Because of the Jackson upgrade, the JSON connector now fails deeply nested records:
    - A record nested more than 1000 levels deep, in any field, now fails as a bad record when PXF parses it.
    - Previously, such a record read normally unless a selected column held the deeply nested value, and a deep enough value overflowed the stack.
    - PXF lifts the string, number, and field-name length limits that Jackson 2.15 and later add, so records that read before still read.
